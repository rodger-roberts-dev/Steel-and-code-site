# Steel & Code — Programming Fundamentals I

## Founding Cohort Product Definition

## Product Name

**Programming Fundamentals I: Python, Automation & Computational Modeling — Founding Cohort**

## Product Type

Instructor-led cohort built on top of the PF1 self-paced course.

## Delivery Model

Students receive access to the same core PF1 curriculum as self-paced learners, but move through the course together on a scheduled 8-week path with live instructor support, community interaction, and additional feedback.

The cohort is not a separate course.

It is the **guided version of the same PF1 product**.

---

# Product Promise

Learn Python fundamentals through automation, problem solving, and computational modeling with direct instructor guidance and a small group of learners moving through the course together.

The founding cohort adds structure, accountability, live teaching, feedback, and community to the PF1 self-paced curriculum.

---

# Founding Cohort Goals

The founding cohort should:

- Deliver the complete PF1 learning experience
- Provide direct access to the instructor
- Create accountability
- Help students stay on pace
- Identify confusing lessons and weak areas
- Generate student feedback
- Produce testimonials and success stories
- Validate the Steel & Code teaching model
- Improve the self-paced product
- Establish the first repeatable cohort process

---

# Target Student

The cohort is designed for students who:

- Want to learn Python but prefer instructor guidance
- Benefit from deadlines and structure
- Want live access to an instructor
- Want help when they get stuck
- Prefer learning with a small group
- Want feedback on projects
- Are new to programming
- Want a practical, applied introduction to Python
- Are interested in automation and computational modeling

No prior programming experience is required.

---

# Cohort Length

**8 weeks**

Students follow the same general progression as the self-paced course.

Recommended pace:

- One primary course week per calendar week
- Approximately 3–5 hours of independent work
- One live session each week

---

# Cohort Size

The first founding cohort should remain intentionally small.

Suggested range:

**8–15 students**

A smaller group allows Steel & Code to:

- Learn what students struggle with
- Provide meaningful feedback
- Test the course platform
- Refine live sessions
- Develop community culture
- Gather detailed feedback

Future cohorts may increase enrollment after the process is proven.

---

# Core Curriculum

All cohort students receive access to the complete PF1 self-paced course.

This includes:

- Approximately 32 instructional videos
- Steel & Code Workbench labs
- Guided examples
- Independent challenges
- Knowledge checks
- Four module projects
- Computational modeling capstone
- Course notes and reference material

The live cohort experience should enhance the self-paced curriculum rather than duplicate it.

---

# Weekly Structure

Each week should follow a predictable rhythm.

## Before the Live Session

Students complete assigned self-paced lessons.

This may include:

- Videos
- Guided labs
- Independent challenges
- Knowledge checks

Students should arrive at the live session with basic exposure to the week's concepts.

---

## Weekly Live Session

Recommended length:

**60–90 minutes**

The live session should focus on:

- Questions
- Difficult concepts
- Debugging
- Worked examples
- Student challenges
- Applied demonstrations
- Project guidance
- Computational modeling

Avoid repeating every video lesson as a traditional lecture.

The self-paced course teaches the core content.

The live session should focus on helping students **use it**.

---

# Suggested Live Session Format

## 1. Opening Check-In

Approximately 5–10 minutes.

Topics:

- Where students are in the course
- Common challenges
- Quick wins
- Questions from the week

---

## 2. Concept Review

Approximately 10–15 minutes.

Review the most important or most difficult concept from the week.

Keep this focused.

---

## 3. Live Build

Approximately 20–30 minutes.

Build or debug a program live.

Examples may include:

- Solving a new problem
- Extending a lesson example
- Debugging intentionally broken code
- Modeling a real-world system
- Responding to student questions

The instructor should explain the reasoning process while coding.

---

## 4. Student Q&A

Approximately 15–20 minutes.

Students may ask about:

- Course concepts
- Workbench problems
- Projects
- Errors
- Algorithms
- Debugging

---

## 5. Next Week Preview

Approximately 5 minutes.

Explain:

- What students should complete next
- Upcoming project milestones
- Important concepts to watch for

# Suggested 8-Week Cohort Schedule

## Week 1 — Programming Foundations

Topics:

- Programming as automation
- Variables
- Data types
- Input and output

Live focus:

Build a complete beginner program from problem statement to working solution.

---

## Week 2 — Calculations and Models

Topics:

- Operators
- Expressions
- Type conversion
- Translating formulas into code

Live focus:

Build a simple computational model such as Ohm's Law or another real-world formula.

---

## Week 3 — Decisions

Topics:

- Boolean logic
- Comparisons
- `if`
- `else`

Live focus:

Build and debug a decision-based program.

---

## Week 4 — Complex Logic

Topics:

- `elif`
- `and`
- `or`
- `not`
- Nested logic

Live focus:

Develop a multi-condition decision system.

Module 2 project review may occur during this session.

---

## Week 5 — Repetition

Topics:

- `while`
- Counters
- Input validation
- Repeated processes

Live focus:

Automate a repetitive task.

---

## Week 6 — For Loops and Modeling

Topics:

- `for`
- `range()`
- Accumulators
- Iterative calculations

Live focus:

Build a model that calculates results across multiple values or time steps.

---

## Week 7 — Building Larger Programs

Topics:

- Functions
- Parameters
- Return values
- Lists
- Files

Live focus:

Break a larger problem into smaller functions and components.

---

## Week 8 — Computational Modeling Capstone

Topics:

- Final project
- Model design
- Testing
- Interpretation

Live focus:

Capstone review, demonstrations, and course wrap-up.

Students may optionally present or demonstrate their projects.

Possible platform:

- Discord

Community channels may include:

```text
# announcements
# introductions
# pf1-help
# workbench-help
# projects
# wins
# general
```

The community exists to support learning, not create another full-time obligation for the instructor.

Students should be encouraged to:

- Ask questions
- Share progress
- Help one another
- Share bugs and solutions
- Celebrate completed projects

---

# Instructor Support

Founding cohort students receive more instructor access than self-paced students.

Possible support includes:

- Weekly live sessions
- Community Q&A
- Project feedback
- Workbench troubleshooting
- General course guidance

Instructor support should have clearly defined boundaries.

The cohort should not imply unlimited one-on-one tutoring.

---

# Project Feedback

Founding cohort students should receive feedback on major projects.

Suggested feedback model:

- Module projects receive brief instructor feedback
- Capstone receives more detailed feedback
- Feedback focuses on:
  - Logic
  - Readability
  - Problem-solving approach
  - Testing
  - Correctness
  - Opportunities for improvement

The goal is not professional code review.

The goal is helping beginners improve their programming process.

---

# Office Hours

Optional office hours may be added if needed.

Possible model:

**One optional 60-minute group office hour per week**

Office hours may be used for:

- Additional questions
- Debugging
- Project help
- Catch-up support

For the first cohort, office hours should only be added if student demand justifies them.

# Founding Cohort Expectations

Students should understand that the founding cohort is the first live delivery of the product.

The course should still be complete and professional, but students may encounter:

- Small platform changes
- Lesson refinements
- New examples added during the cohort
- Workbench improvements
- Schedule adjustments
- Experimental features

Founding students should be invited to provide feedback throughout the course.

---

# Feedback Process

Feedback should be intentionally collected.

Possible checkpoints:

## Week 2

Ask:

- Is the pace reasonable?
- Are the videos clear?
- Is the Workbench easy to use?

## Week 4

Ask:

- Which lessons have been most useful?
- Where have you struggled?
- Are the projects appropriately difficult?

## Week 8

Ask:

- What changed for you during the course?
- What should be improved?
- Would you recommend the course?
- What topic would you want next?

---

# Testimonials

After the cohort, students who had a positive experience may be invited to provide a testimonial.

Possible prompts:

- What problem were you trying to solve before joining?
- What did you learn?
- What did you build?
- What surprised you?
- Who would you recommend the course to?

Permission should be obtained before publicly using student names, photos, or testimonials.

# Founding Cohort vs Self-Paced

| Feature | Self-Paced | Founding Cohort |
|---|---|---|
| Full PF1 Curriculum | Yes | Yes |
| Workbench Access | Yes | Yes |
| Videos | Yes | Yes |
| Guided Labs | Yes | Yes |
| Module Projects | Yes | Yes |
| Capstone | Yes | Yes |
| Weekly Live Sessions | No | Yes |
| Instructor Q&A | Limited | Yes |
| Project Feedback | No / Limited | Yes |
| Community | Optional | Yes |
| Group Accountability | No | Yes |
| Cohort Schedule | No | Yes |

The cohort's value comes from:

**Guidance + Feedback + Community + Accountability**

The content itself remains shared with the self-paced course.

---

# Product Boundary

Do not turn the founding cohort into unlimited private tutoring.

The core product is:

**A structured 8-week guided learning experience built around PF1.**

The founding cohort should remain repeatable.

If the delivery model requires the instructor to personally support every student constantly, it will be difficult to scale.
